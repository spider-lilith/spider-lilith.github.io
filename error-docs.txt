# ✅ Summary of Issues Encountered & Resolved

This project surfaced several **common PHP pathing, session, and configuration errors** that typically appear once an application grows beyond a few pages. All of them were resolved by introducing clearer separation of concerns and consistent routing rules.

***

## 1️⃣ `$_SESSION` Undefined / Access Denied Errors

### ❌ Symptoms

*   Warnings such as:
    Undefined global variable $\_SESSION
    Trying to access array offset on value of type null
*   Dashboard immediately showing **“Access denied”** even when logged in

### ✅ Root Cause

*   `session_start()` was defined in `header.php`
*   The dashboard file was accessed **without including the header**
*   PHP sessions do not exist unless explicitly started

### ✅ Resolution

*   Introduced a dedicated `includes/session.php`
*   Centralized `session_start()` there
*   Included `session.php` in all logic-only and protected files

✅ Result: Session data became reliably available everywhere.

***

## 2️⃣ Relative Path Failures in Dashboards

### ❌ Symptoms

*   Errors like:
    Failed opening required includes/db.php
*   PHP looking for files in paths such as:
    includes/dashboards/includes/db.php

### ✅ Root Cause

*   Use of relative paths like:
    ```php
    require 'includes/db.php';
    ```
*   Relative paths are resolved from the **current file’s directory**, not the project root

### ✅ Resolution

*   Replaced relative paths with filesystem-safe includes:
    ```php
    require_once __DIR__ . '/../db.php';
    ```
    or
    ```php
    require_once ROOT_PATH . '/includes/db.php';
    ```

✅ Result: Includes work from any directory depth.

***

## 3️⃣ Logout Redirect Broken

### ❌ Symptoms

*   Logout “worked” but user stayed on the same page
*   Or browser tried to access:
    /includes/dashboards/logout.php

### ✅ Root Cause

*   Logout form used a relative action:
    
*   Browser resolved it relative to the dashboard folder

### ✅ Resolution

*   Introduced `BASE_URL`
*   Updated form action to:
    ```php
    action="<?= BASE_URL ?>logout.php"
    ```

✅ Result: Logout redirected correctly from all pages.

***

## 4️⃣ `BASE_URL` Undefined in `logout.php`

### ❌ Symptoms

    Fatal error: Undefined constant "BASE_URL"

### ✅ Root Cause

*   `BASE_URL` was defined inside `header.php`
*   `logout.php` does not (and should not) include the header

### ✅ Resolution

*   Created `includes/config.php`
*   Moved `BASE_URL` definition there
*   Required `config.php` from all files that need configuration

✅ Result: Constants became globally reliable.

***

## 5️⃣ CSS Not Loading on Dashboards

### ❌ Symptoms

*   Layout broke or appeared unstyled when viewing dashboards
*   CSS loaded correctly on root pages but not subfolders

### ✅ Root Cause

*   CSS linked using a relative path:
    
*   Browser resolved path relative to `/includes/dashboards/`

### ✅ Resolution

*   Switched to absolute, base‑URL‑based paths:
    ```php
    href="<?= BASE_URL ?>includes/css/styles.css"
    ```

✅ Result: CSS loads correctly everywhere.

***

## 6️⃣ Dashboard Routing Confusion

### ❌ Symptoms

*   Confusion about whether dashboards belong in `/includes/` or root
*   Role checks duplicated across files

### ✅ Root Cause

*   No central dashboard entry point
*   Dashboards treated as both public pages and includes

### ✅ Resolution

*   Created a **single public router**:
    /dashboard.php
*   Role‑specific dashboards remain in:
    /includes/dashboards/
*   `dashboard.php` decides which to include

✅ Result: Clean URLs, centralized access control, safer architecture.

***

## 7️⃣ PDO Error: `Unknown database 'task2_glharray'`

### ❌ Symptoms

    Array to string conversion
    Unknown database 'task2_glharray'

### ✅ Root Cause

*   `DB_CHARSET` was accidentally defined as an **array**
*   When concatenated into the DSN, PHP converted it to the string `"Array"`

### ✅ Resolution

*   Corrected `DB_CHARSET` in `config.php`:
    ```php
    define('DB_CHARSET', 'utf8mb4');
    ```

✅ Result: PDO connection restored and stable.

***

## ✅ Final Architecture Achieved

What you now have is a **professional‑grade PHP structure**:

*   `config.php` → constants & environment
*   `session.php` → session lifecycle
*   `header.php` → HTML + navigation only
*   `dashboard.php` → routing & access control
*   `includes/dashboards/` → protected internal views
*   `BASE_URL` → all browser paths
*   `ROOT_PATH` → all PHP includes

***

## ✅ Why This Matters (Reflection-Ready)

*   Eliminated fragile relative paths
*   Prevented “headers already sent” errors
*   Made login → dashboard → logout deterministic
*   Improved security by hiding includes from direct access
*   Scales cleanly if more roles or pages are added
