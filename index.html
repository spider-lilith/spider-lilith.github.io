h1>OSP Task 2 – Day‑by‑Day Development Plan

Stack: HTML, CSS, JavaScript (Frontend) | PHP & MySQL (Backend)

Environment: XAMPP

Key reminder:
Task 2 is about demonstrating secure, functional, iterative development, not building a perfect website.

Day 1 – Database Setup ✅

  • Create MySQL database in phpMyAdmin
  • Import tables based on Task 1 ERD
  • Check primary and foreign keys

This counts as Iteration 1 – Design to Implementation.

Day 2 – Backend Setup & Database Connection

  • Create project folder structure in htdocs
  • Create db.php for MySQL connection
  • Use mysqli or PDO
  • Test connection by selecting data from database

Evidence gained: modular structure, maintainable code, backend language usage.

Day 3 – Product Catalogue (Customer View)

  • Create products.php
  • Retrieve products from database
  • Display product name, price and stock
  • Add basic CSS for readability
  • Handle errors (no products / DB failure)

Testing focus: normal, boundary and extreme data.

Day 4 – Producer Features (Add Product + Update Stock)

  • Create Add Product form
  • Validate inputs server‑side
  • Insert data using prepared statements
  • Create Update Stock form
  • Prevent negative stock values

Important: Intentionally find an error → fix it → document it.

Day 5 – Orders (Simplified)

  • Create simple “Place Order” functionality
  • Reduce product stock when order placed
  • Store order in database
  • Prevent ordering more than available stock

No payment system required.

Day 6 – Testing & Iterative Development Evidence

  • Complete Test Log with valid, invalid and boundary data
  • Record failed tests and fixes
  • Write Iteration 1 & Iteration 2 summaries
  • Perform regression testing after fixes

This day secures high marks.

Day 7 – Review, Security & Final Checks

  • Write Review section (useful, usable, accessible, credible)
  • Document security measures:
    • Password hashing
    • Prepared statements
    • Input sanitisation
    • Role‑based access control
  • Complete version log
  • Complete asset log
  • Final regression testing

Always include these phrases in your documentation:

  • Iterative development process
  • Regression testing
  • Robust validation
  • Defensive programming
  • Referential integrity
  • Role‑based access control
  • Prepared statements
  • Input sanitisation
  • Modular structure
  • Version control
